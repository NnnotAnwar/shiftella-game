# Shiftella 0.2 — build mode, hands-on equipment, the character card

Owner decisions, 2026-11-26. Read `docs/GAME-BRIEF.md` first (it still rules: player-first,
cozy, nothing can be failed, CZ/EN/UA/RU, everything in the repo in English).

Owner taste that applies to every task below:

* **Compact & readable UI.** The owner hates oversized UI. Small type from the theme scale,
  tight padding, no empty space inside cards — but always legible at UI scale 1.0 and 1.3.
* **Fast actions over popups.** One click / one hold does the thing, an Undo toast if it
  matters. No confirm dialogs, no mini-menus for frequent actions, no helpers that open by
  themselves.
* **Player-first.** Karolina does it with her hands; it must feel good to click (a sound, a
  small animation, a visible result in the café).
* Nothing may become *required* to finish the story (a no-build, no-equipment player still
  reaches «Light in the Window»), but every new thing must be worth doing.

There are four work packages, each owned by one agent in its own worktree
(`~/WebDev/2026/shiftella-game-wt/<name>`, branch `agent/<name>`).

## A. `build-ux` — a build mode that is pleasant to use

Owns: `src/screens/game/build.rs` (and new files `src/screens/game/build_*.rs`), the build
ghost / overlay drawing, `MoveFurniture` plumbing in the UI, `assets/i18n/src/build_ux.tr`.

1. **Move by dragging.** In build mode, press on a placed piece and drag it; a table brings
   its chairs along (chairs within 1 tile that face it). Free, rotatable while dragging (R),
   Ctrl+Z undoes. A piece in use (a seated guest, a busy station) shows why it can't move.
   The sim already has `Command::MoveFurniture`.
2. **Coziness preview.** While a piece is held (new or moved) the coziness meter shows the
   change it would make (e.g. `+0.6`), and a soft overlay shows light (warm pools) and beauty
   reach (the 3-tile radius used by guests). Add a pure query on `World` such as
   `coziness_preview(&content, def, x, y, rot) -> f32`, with tests.
3. **Readable cards.** Each card shows small chips for what the piece gives: coziness, comfort
   (seat), light, music, station/appliance, "seats 2". Hover = the description and the exact
   numbers. Locked cards say *how* to unlock ("from night 6", "when Lori is invited").
4. **Compact panel.** Lower and narrower than now so it doesn't cover the counter; scrollable
   card row with a visible scroll hint; tabs stay. The hall may pan/zoom so the area being
   built is never under the panel.
5. **Theme hints.** Locked themes show their unlock condition in plain words (reputation 50
   *or* 3 000 CZK tips, the 1979 timetable *or* night 18, Filip's story, garlands).
6. A **"wanted" badge slot** on cards: render a little face + "Filip is waiting" when
   `World::build_wishes(&content)` (provided by package C) lists that def/tag. Until C lands,
   call a stub that returns the current hard facts (Filip → `power_socket` from night 7,
   Lori → `stage` once `lori_invited`, Hana → armchair + floor lamp). Put the stub in
   `src/sim/build_wishes.rs` with the signature below; C will replace its body.

   ```rust
   pub struct BuildWish { pub who: String /* regular or staff id */, pub def: Option<String>,
                          pub tag: Option<String>, pub reason_key: String }
   impl World { pub fn build_wishes(&self, content: &Content) -> Vec<BuildWish> }
   ```

## B. `equipment` — hands-on appliances at night

Owns: `src/screens/game/hands*.rs`, `src/sim/hands.rs` (+ new `src/sim/equipment.rs`),
appliance render states in `src/render/` (steam, pot, oven light, lamp glow switches),
`assets/data/handson.ron` equipment entries, `assets/i18n/src/equipment.tr`.

Every appliance becomes clickable during the prep half hour and the night (a new `Intent`
per kind, keyboard **E** picks the nearest one too). Short, can't be failed, each has a
visible effect and a sound:

* **Coffee machine** — prep: *warm it up* (hold; it hisses, a lamp lights; opening checklist
  item done by hand). Night: *pull a tray ahead* before a train → the next 3 plain coffees are
  served instantly. Worn (`wear ≥ 0.5`): it sputters, *purge it* (hold) → wear resets
  (this replaces any repair cost for appliances). Closing: *clean the group head* (closing
  checklist `clean_machine` by hand).
* **Stove** — prep: *put a pot of kulajda on*; at night the pot bubbles now and then, a click
  stirs it → soup orders are faster for a while. Untouched it simply keeps warm.
* **Oven** — prep: *bake grandma's medovník*; a timer dings, click to take it out → cake
  slices are served without waiting tonight.
* **Fridge** — click opens the pantry; prep: *take the milk out* → the first lattes are faster.
* **Lamps / floor lamps / pendant lamps** — click toggles (sim `SetFurnitureOn`), light and
  coziness change; the opening checklist "lights" item is done by hand.
* **Register** — closing: *count the till* (a short satisfying count with tonight's numbers).
* **Trash bin** — closing: *take the trash out*: Karolina steps out of the door for a moment,
  sometimes the station cat is there.
* Chairs/tables keep their current interactions.

The prep half hour (21:30–22:00) should now have something by hand at each appliance.
Helpers with the matching duty can still do these (they are delegated chores), but the
player doing them by hand is faster and gives a small bonus. Tutorial: one GotIt step on
night 1 ("Things in the café can be used — click the coffee machine to warm it up").

## C. `build-content` — reasons to build

Owns: new sim modules `src/sim/build_wishes.rs` (replacing A's stub body), `src/sim/corners.rs`,
`src/sim/attic.rs`, data `assets/data/build_wishes.ron`, `corners.ron`, `attic.ron`,
`assets/i18n/src/build_content.tr`, the back-room expansion, before/after polaroids.
Does **not** edit `src/screens/game/build.rs` (A owns it); UI for C goes in new files
(`src/screens/game/attic_ui.rs`, …) and is wired by the integrator.

4. **Requests from guests and staff** — data-driven wishes ("Hana: a quiet corner", "Vera: a
   seat by the window", "Filip: a table with a socket", staff: "a coat rack, please"). They
   appear as a line from the person and a card in the Shiftella app (Handover / a new
   "Requests" section). Fulfilling one: the person reacts, a small reward (trust, a tip, a
   napkin), story arcs keep their existing conditions. `World::build_wishes` returns them.
6. **Corners (sets)** — pieces placed together form a named corner: *reading nook* (armchair +
   floor lamp + bookshelf), *window spot* (window seat + plant + lamp), *little stage* (stage +
   lamp), *coat corner*… Each corner gives a coziness bonus and attracts its guest archetypes.
   Detected by the sim, shown as a soft label in build mode.
7. **Grandma's attic / flea market** — once a week a few second-hand pieces at a lower price,
   each with a one-line story ("Grandma's sewing chair"). Unique, data-driven.
8. (Repair moved to B for appliances; furniture wear is out of scope.)
9. **The back room** — a late-game goal: pay to reopen grandma's back room (a second small
   hall, more seats and floor to decorate). Story-safe: optional, available from ~night 15,
   priced so a Cozy player can afford it by night 20.
10. **Before / after** — when the hall changes noticeably in a day (coziness +1 or a corner
    formed), the next morning's polaroid choices include a "before / after" shot for the
    journal.

## D. `crew-card` — the character card (clicking Karolina or a helper)

Owns: `src/screens/game/panels.rs` crew part (move it to a new `src/screens/game/crew_ui.rs`),
`assets/i18n/src/crew_card.tr`. Read-only access to sim queries; add small pure queries in
`src/sim/staff.rs` only where needed.

Today: a list + a detail card with unlabelled triple bars, five identical "4" skill bars,
relationship chips that read "Zdeněk · colleagues", and Karolina shows "waiting for work" and
a *Break* button. Rework into a card that answers "who is this, what are they doing, how are
they, what can I do":

* **Karolina's card is different** — she is the player: tonight's to-do (what she is doing
  now and her queue), her hands-on stats (perfect cups, tips, rhythm), no break/energy
  nonsense on Cozy.
* **Helper card** — portrait + name + role; *now*: the current task in words ("washing the
  dishes", "on the way to table 4") and the next one; tonight's shift times; **duties as
  toggles right in the card** (dishes, floor, register, bar, kitchen — the same model as the
  Duties board, H); mood/energy as labelled bars with the reason ("tired after a double");
  skills as words/levels only where they differ; traits as chips with hover explanations;
  their wish for the rozpis; one line about who they get along with.
* Quick actions (one click, no popups): *Follow*, *Break* (Classic only, or when tired),
  *Send home*, *Open in rozpis*. Hiring candidates stay in the list, with what they are good
  at in one line.
* Clicking a person in the café opens their card anchored near them or in the left panel;
  Esc closes; arrow keys step through the crew.
* Compact: the card must fit at 1280×720 and UI scale 1.3 without truncation.

## E. `guest-names` — strangers get a description, then a name (owner chose «option C»)

Owns: new `src/sim/names.rs`, `assets/data/guest_names.ron` (or an extension of the staff
name pools), `assets/i18n/src/guest_names.tr`, new `src/screens/game/guest_label.rs`.
Minimal edits to `hands_ui.rs::guest_name` and `world_view::guest_one` (the `equipment` agent
works in hands*.rs — keep the change to those functions only).

Today every stranger is labelled with the singular of its archetype ("Conductor",
"Traveller", "Medic"), so the queue strip reads "Conductor… Conductor… Conductor…".

* Each guest gets at spawn (deterministic, from the world RNG, no balance effect): a
  presentation (f / m), a first name from international pools with a Czech note (Czech,
  Slovak, Ukrainian, Polish, German, Vietnamese-Czech, English…; a Cyrillic form for uk/ru),
  and a **description** chosen from whole localized phrases per archetype × presentation and
  per visible accessory ("a woman in a yellow raincoat", "a man with a suitcase", "a nurse
  after her shift", "a student in headphones", "a cabbie in a cap") — whole phrases, never
  glued words, so cs/uk/ru grammar stays right. The look generator matches the presentation.
* Until Karolina gets to know them the guest is shown by the description. Greeting /
  talking / serving them reveals the name with a small line ("I'm Hanna, thank you!"); from
  then on the name is used over their head, in the queue strip, the order card, bubbles and
  the night log. A party reads "Hanna + 2".
* Regulars keep their names. No recurring strangers across nights (owner: option C only).
* Labels must fit: the queue strip shows a short form (name, or a 1–2 word description) with
  the full description on hover; no "Провод…" truncation in cs/ru at 1280×720.
* Saves: new guest fields `#[serde(default)]`; a guest loaded without them gets them on load.

## Rules for every agent

* Toolchain: `export PATH="/opt/homebrew/opt/rustup/bin:$HOME/.cargo/bin:$PATH"`.
* Work only in your worktree and only in the files you own; shared files (`src/sim/types.rs`,
  `src/sim/world.rs`, `src/sim/mod.rs`, `src/screens/game/mod.rs`) — minimal, additive edits
  (new enum variants at the end, new fields with `#[serde(default)]`), no reformatting.
* Translations: your own `assets/i18n/src/<package>.tr`, all four languages (cs, en, uk, ru),
  natural, not literal. Regenerate with `cargo run --example content_i18n_build`.
* Saves: new world fields need `#[serde(default)]`; old 0.1.x saves must load.
* Tests: `cargo test` and `cargo clippy --all-targets` clean. Add sim tests for every new rule.
  The full-story bot tests (`src/sim/tests_t10.rs`) must still pass, and a no-build run still
  reaches the light ending.
* UI rule: call `ui.glass(r)` **before** `ui.interact(id, r)`.
* Screenshots to verify, invisible (no windows on the owner's screen):
  `SHIFTELLA_HIDDEN=1 SHIFTELLA_SETTINGS=<tmp>/s.ron SHIFTELLA_SAVES=<tmp>/saves SHIFTELLA_LANG=ru
  SHIFTELLA_SCENE=<scene> SHIFTELLA_NIGHT=8 SHIFTELLA_TIME=00:30 SHIFTELLA_SHOT=<tmp>/x.png
  target/release/shiftella-game` (add a new `SHIFTELLA_SCENE` for your feature). Check cs and
  ru for overflow.
* Never commit `assets/audio/`, `.env`, `shots/`, `dist/`. Commit on your branch, don't push,
  don't merge — the integrator merges.
* Document what you added in `docs/PLAYING.md` (player view) and `docs/SIM.md` (sim API).
